# 小窗消失的原因调查

## 已确认的原因与边界

2026-10-31 两次运行中消失均有 Defender 检测和隔离事件相对应。第二次进程退出码为 0，但同一时刻有 1117 隔离记录，不能用退出码证明正常结束。未找到相应的 Windows Application Error 事件。

还有一次更有区分力的证据：19:27:38 只对 dist 中的 EXE 执行 Get-FileHash、未运行该副本，就出现了检测；19:28:04 完成隔离。这证明运行播放器、按 F8 或持续分配播放内存都不是检测所必需的条件。当前主要问题是 Defender 对该 EXE 的静态分类。微软的机器学习分类器不提供具体触发代码，尚不能认定某一函数是原因。

## 固定基线与有意义的改动

被隔离构建 SHA256：`35af58597bb10239bd2db0334bd1df0477dffe88c537dce2d7516d74e8566574`。

改动前源文件保存于 `build/diagnostics/baseline-source`，原隔离文件未恢复。新实现删除前端自制的 yt-dlp 进程启动、管道、挂起/恢复线程、作业组和终止进程代码，改由 libmpv 官方自带的 ytdl hook 完成在线解析；公开播放接口保留为一次有界回退。C++ 窗口、控件、热键和第三方依赖不变。此改动减少重复的系统进程管理代码，也提供一个具体、可检查的对照。它不等于已证明上述代码导致误报。

## 验证顺序

1. 完成离线回归和 PE 导入检查。
2. 不运行 GUI，记录新 EXE 哈希并检查持续可读性和新 Defender 事件。
3. 静态检查通过后，验证 libmpv 直接解析样例 P2，检查 720p、音频、暂停、跳转及继续。
4. 再启动同一构建检查窗口和热键，最后才测持续运行和内存。每一关失败都保存具体证据，不重复盲跑。

## 后续退出证据

程序写入 `data/session.jsonl`，只记时间、PID、事件和数字，不记链接、登录信息或视频地址；文件超过 1 MiB 会覆盖。`scripts/run-app.ps1 -WaitSession` 在退出后等待三秒供系统事件写入，再调用 `scripts/collect-diagnostics.ps1`，把本次生命周期与 Defender 1116/1117、Application 1000/1001 对齐，保存至 `build/diagnostics/exit-PID.json`。报告会清理本机用户名和工作目录。脚本显式过滤 UTC 起止时间、准确 EXE 路径和 PID；只有文件路径、没有 PID 的记录单独标记，不认定为该进程被隔离。1117 必须同时包含目标进程、隔离动作和成功状态才报告成功隔离。没有对应证据时明确记录 `no_exit_cause_recorded`，不凭退出码猜测。时间边界、其他 PID/路径、失败隔离和应用异常的模拟事件回归已通过。
